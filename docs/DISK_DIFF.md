# WinDirStat-Diff

Первая версия режима сравнения двух сохранённых снимков в нативном WinDirStat.
Основа: `windirstat/windirstat`, commit `40d77b693e1e1059aba21412268b3cbaa09cec62`.
Изменения подготовлены в ветке `disk-diff`.

## Что реализовано

- При запуске без аргументов открывается окно выбора старого и нового снимков.
- Команда **Файл → Сравнить снимки**, сочетание **Ctrl+D**.
- CSV и JSON в формате экспорта WinDirStat; английские, русские и соответствующие текущему языку интерфейса поля.
- Сопоставление по нормализованному абсолютному пути без сканирования каталогов и чтения содержимого файлов.
- Четыре класса: добавлен (зелёный), удалён (красный), вырос (оранжевый), уменьшился (синий).
- Площадь плитки соответствует модулю изменения размера. Рост с 200 МБ до 1 ГБ даёт плитку на 800 МБ.
- Дерево содержит изменившиеся файлы и их родительские папки. Неизменившиеся файлы отсутствуют.
- В дереве: размер A, размер B, итоговая разница; сортировка по объёму изменений.
- Легенда показывает объём и количество файлов отдельно для каждого класса в текущей области карты.
- Наведение на папку в дереве или на рамку папки в карте подсвечивает её изменившихся потомков.
- Наведение на плитку подсвечивает изменения того же класса внутри её папки.
- **Файл → Подсветить класс изменений** позволяет выбрать только добавленные, удалённые, выросшие, уменьшившиеся или все файлы.
- Строка состояния и подсказка показывают путь, размеры A/B и дельту; для папок — суммы по четырём классам.
- Проверяются обязательные поля, целостность JSON/CSV, количество файлов при наличии этого поля, дубликаты, иерархия и совпадение корней.
- Свободное и неизвестное пространство исключаются из файловой карты и из размеров папок A/B.
- Загрузка и построение дерева выполняются с индикатором и отменой. Ошибка или отмена сохраняют предыдущий открытый результат.
- В режиме сравнения отключены очистка, изменение файлов, наблюдение, повторное сканирование и сохранение дельт как обычного снимка.
- Обычное сканирование доступно через **Файл → Выбрать диски/папки**. Его результат можно сохранить в CSV/JSON для следующего сравнения.

## Как пользоваться

1. В современном WinDirStat полностью просканируйте нужную папку или диск и сохраните результат в CSV/JSON — это снимок A.
2. Позже просканируйте тот же набор папок с теми же фильтрами и параметрами, сохраните снимок B.
3. Запустите WinDirStat-Diff, выберите A и B и нажмите **Сравнить**.
4. По умолчанию сравнивается логический размер файлов. Для физического размера выберите второй вариант в окне сравнения.
5. Наводитесь на папки в дереве; при необходимости выбирайте класс подсветки через меню Файл.

Для смены способа измерения откройте сравнение заново через Ctrl+D. Переключение обычных режимов размера в меню карты заблокировано, поскольку другой способ измерения требует пересчитать классификацию файлов.

Готовые примеры лежат в `tests/disk-diff/fixtures` (в переносимом пакете — в `examples`): `before-en.json` и `after-ru.json`, а также их CSV-версии. Создавать папку `C:\DiskDiffTest` для открытия примеров не требуется.

Ожидаемый результат примеров в логическом режиме:

| Класс | Объём | Файлы |
|---|---:|---:|
| Добавлены | 200 байт | 2, включая пустой файл |
| Удалены | 1 000 байт | 1 |
| Выросли | 800 байт | 1 |
| Уменьшились | 500 байт | 1 |
| Итог | −500 байт | |
| Площадь карты | 2 500 байт изменений | |

В физическом режиме примеров итог равен нулю, но на карте остаются четыре класса изменений по 4 096 байт: они не взаимоуничтожаются.

## Командная строка

```powershell
.\WinDirStat-Diff.exe /Compare "C:\Snapshots\before.json" "C:\Snapshots\after.json"
.\WinDirStat-Diff.exe /ComparePhysical "C:\Snapshots\before.csv" "C:\Snapshots\after.csv"
```

Сохранены исходные параметры WinDirStat для сканирования и сохранения результатов:

```powershell
.\WinDirStat-Diff.exe /SaveTo "C:\Snapshots\today.json" "C:\Users"
```

## Сборка через GitHub Actions

Устанавливать Visual Studio на свой компьютер для этого пути не требуется.

1. Изменения должны находиться в собственном форке WinDirStat, в ветке `disk-diff`.
2. Для нового форка может понадобиться включить Actions на вкладке **Actions**.
3. Откройте workflow **Build Disk Diff**, выберите **Run workflow** и ветку `disk-diff`. При последующих отправках в эту ветку сборка запускается автоматически.
4. После успешной сборки скачайте артефакт **WinDirStat-Diff-Windows-x64**.
5. Распакуйте архив, запустите `WinDirStat-Diff.exe`. Пустой файл `WinDirStat-Diff.ini` рядом хранит настройки этого форка отдельно от установленного WinDirStat.

Workflow проверяет ядро на Linux и Windows, компилирует приложение x64, проверяет стартовое окно и открытие примеров, затем упаковывает переносимую программу. Здесь используются Windows 2025 runner, Visual Studio 2022 и принудительный toolset **v143** вместо исходного **v145** в проекте. Подпись EXE и MSI-инсталлятор в этот сценарий не входят.

## Локальная сборка, если компилятор уже установлен

Нужны инструменты C++ Visual Studio 2022 17.14 или новее, ATL и Windows SDK. Пакет **Visual C++ Redistributable** — только библиотеки для запуска программ; он не заменяет компилятор.

```powershell
.\scripts\test-diff-core.ps1 -BenchmarkFiles 250000
.\scripts\build-diff.ps1 -Toolset v143
.\tests\disk-diff\Test-Ui.ps1 -Exe .\build\WinDirStat-Diff_x64.exe
```

Результат сборки: `build\WinDirStat-Diff_x64.exe`. Скрипты не устанавливают компоненты Visual Studio и не требуют прав администратора.

На Linux можно проверить независимое ядро:

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Werror -pedantic -Iwindirstat \
  windirstat/SnapshotDiffCore.cpp tests/disk-diff/TestCore.cpp -o /tmp/test-diff-core
/tmp/test-diff-core
/tmp/test-diff-core --benchmark 1000000
```

## Границы первой версии

- Сопоставляются пути, не NTFS file IDs. Переименование или перенос файла показываются как удаление и добавление.
- Изменение содержимого при неизменном выбранном размере не отображается; хеширование не выполняется.
- Физические размеры взяты из записей экспорта. Жёсткие ссылки могут учитывать выделенные байты несколько раз, а удаление одной ссылки не обязательно освобождает эти байты. Этот режим не является измерением изменения свободного места на томе.
- Добавленные и удалённые файлы нулевого размера присутствуют в дереве и счётчиках, но не занимают площадь на карте. Пустые каталоги без изменившихся файлов не отображаются.
- Пути сопоставляются без учёта регистра. Каталоги с несколькими именами, различающимися только регистром, отклоняются как неоднозначные.
- MTP и другие неподдерживаемые типы записей отклоняются. Старые версии формата с другими флагами также могут быть несовместимы: снимки можно создать самим этим форком.
- Экспорт не хранит полный набор настроек сканирования. Совпадение корней проверяется, одинаковые фильтры нужно обеспечить при сохранении снимков.
- Автоматические снимки и обнаружение перемещений пока не реализованы.
