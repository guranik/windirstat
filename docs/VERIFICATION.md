# Проверка WinDirStat-Diff

Дата подготовки: 13 октября 2026 года.
База: upstream commit `40d77b693e1e1059aba21412268b3cbaa09cec62`.

## Выполнено

- Независимое ядро скомпилировано GCC в режиме C++17 с `-Wall -Wextra -Werror -pedantic`.
- Все **294 проверки** прошли. Они охватывают CSV/JSON, русский/английский, четыре класса изменений, размеры логические/физические, нулевые файлы, смену файла на папку, Unicode и JSON escapes, UNC/длинные пути, перестановку снимков, одинаковые снимки, повреждения/обрезание, заявленное число файлов, несовпадающие и перекрывающиеся корни, дубликаты, отмену и переполнение.
- Случайные данные: 20 наборов по 2 000 файлов; проверены независимые ожидаемые суммы и сохранение байтов при объединении снимков.
- Те же проверки прошли с AddressSanitizer и UndefinedBehaviorSanitizer. LeakSanitizer отключён в этой среде: доступ к `/proc/.../task` ограничен; проверка утечек здесь не выполнялась.
- Проверены XML проекта и фильтров, отсутствие конфликтов новых resource IDs, наличие используемых строк на EN/RU и `git diff --check`.
- По исходникам проверено, что сравнение не вызывает загрузчик живого дерева, сканер, `SetDone()` для томов или запросы владельца файлов. Размеры дельт не экспортируются как обычный снимок.

## Измерение скорости

Среда: Linux, GCC, `-O2`. Генерация тестовых CSV выполнялась до замера; чтение файлов включено в замер. В каждом снимке — 1 000 000 файлов, стандартные девять полей CSV, короткие пути. В результирующем diff — 200 000 файлов. Эти данные синтетические и не отражают структуру конкретного диска пользователя.

| Этап | Время |
|---|---:|
| Прочитать и проверить снимок A | 2,000 с |
| Прочитать и проверить снимок B | 1,885 с |
| Сопоставить файлы и вычислить дельты | 0,637 с |
| Всего чтение + проверка + diff | 4,522 с |

Пиковая резидентная память процесса: **586 948 KiB**, примерно **573 MiB**. Здесь не учитываются UI-объекты CItem, построение и отрисовка карты. Измерение сделано до последней проверки перекрывающихся корней; эта проверка обрабатывает только набор корней, а не строки файлов.

Прежний замер на 200 000 файлов использовал сокращённые CSV с четырьмя обязательными полями: чтение 0,478 с, сравнение 0,095 с, пик около 119 MiB. Его нельзя напрямую сравнивать с полным форматом из таблицы выше.

Сопоставление использует хеш-таблицы путей; ожидаемая сложность — O(N + M) при фиксированной длине путей. В памяти находятся компактные записи двух снимков. Полные деревья CItem для них не создаются: они строятся только для изменившихся файлов и родительских папок.

Равенство скорости с исходным WinDirStat и скорость на Windows 10 пользователя пока не измерены.

## Windows: подготовлено, ещё не выполнено

В текущей среде нет Windows/MSVC и рабочего собственного форка для отправки ветки. Поэтому:

- Полный Windows EXE пока **не собран**.
- Сборка через VS 2022/v143 и поведение интерфейса пока **не подтверждены запуском**.
- Скрипт `tests/disk-diff/Test-Ui.ps1` подготовлен для проверки стартового окна, открытия EN/RU-примеров, итоговых −500 байт, заполненного видимого дерева и заблокированного экспорта дельт. Здесь он не запускался.
- Подсветку папок, цвета/легенду, DPI, изменение размеров окна и взаимодействие с картой нужно дополнительно посмотреть на Windows после сборки.

Workflow `.github/workflows/build-disk-diff.yml` сначала проверит ядро на Linux и Windows, затем соберёт x64-приложение, выполнит проверку интерфейса и только после успешных шагов выдаст переносимый артефакт. При ошибке сборки или проверки её нужно исправить по журналу Actions до выдачи готового EXE.
